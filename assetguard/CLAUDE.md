# 개발 작업 지침

## 프로젝트

정보시스템 취약점 관리는 가상 부서별 정보시스템 자산과 보안취약점 대응 흐름을 보여주는 한국어 정적 웹 시연 프로그램이다. 요구사항과 실행·시연 절차는 PRD.md를 먼저 읽는다. 이 파일은 Claude Code와 Codex 등 개발 에이전트가 참고할 프로젝트 지침이며 특정 도구 설치를 전제하지 않는다.

## 구조와 실행

- index.html: 화면 골격. style.css 연결 후 logic.js, app.js 순서로 로드한다.
- style.css: 모든 스타일과 반응형 레이아웃.
- logic.js: 가상 자료와 판정 함수. 화면·저장 코드와 분리한다.
- app.js: 렌더링, 사용자 조작, localStorage, 수집·알림·조치 흐름.
- server.py: localhost 정적 서버와 NVD CVE API·CISA KEV 중계기. 표준 라이브러리만 사용한다.
- 실행은 `python server.py` 후 http://127.0.0.1:8080 에서 확인한다. `NVD_API_KEY`는 선택 환경변수이며 브라우저에 전달하거나 저장하지 않는다.
- 기존 localStorage 키는 assetguard-demo-v1이다. 스키마 변경 시 마이그레이션 또는 별도 버전 키를 검토한다. 사용자 데이터를 임의로 초기화하지 않는다.

## 유지할 동작

- 가상 DEMO-CVE 자료와 실제 NVD/CISA 조회 결과를 화면과 데이터 흐름에서 분리한다. 조회한 CVE/CVSS/KEV는 실제 출처로 표시하고 실제 패치·외부 통보가 수행된 것처럼 설명하지 않는다.
- 가상 CVE ID는 DEMO-CVE 접두사를 유지한다.
- 개발언어만으로 영향 여부를 확정하지 않는다.
- 버전 누락은 판정 불가, 미지원 버전 형식은 확인 필요로 처리한다.
- 숫자 버전 하한 포함·상한 제외 규칙을 유지한다.
- 알림은 판정별 서명으로 중복을 방지한다. 실제 외부 메시지를 발송하지 않는다.
- 검증 완료는 비해당 판정과 증빙이 모두 있어야 한다. 재노출 시 상태를 다시 연다.
- 등록·변경·수집·알림·조치는 감사 이력을 남긴다.
- 사용자 입력은 esc()로 이스케이프한 후 HTML에 삽입한다. 원문을 innerHTML에 직접 넣지 않는다.
- 초기화는 확인 화면을 거친다. 실제 비밀정보·부서 자료를 예제에 포함하지 않는다.

## 변경 후 검증

1. `node --check logic.js` 및 `node --check app.js`로 구문을 검사한다(Node.js 설치 환경).
2. `python -m py_compile server.py` 및 `/api/real-vulnerabilities` 응답으로 서버와 출처 데이터를 검사한다.
3. PRD.md의 시연 시나리오와 검수 기준을 수행한다.
4. 9.0.0/9.0.9/9.0.10 및 버전 공란을 확인한다.
5. 반복 수집·반복 통보, 장애 복구, 패치 후 재판정, 검증 완료 후 재노출을 확인한다.
6. 데스크톱과 좁은 화면에서 표·모달·메뉴를 확인한다.
7. 예약 수집, DB 저장, 인증·권한 등을 추가하면 PRD.md의 구현 범위와 화면 안내도 함께 수정한다.

## 배포

이 폴더 자체를 정적 호스팅 루트로 사용할 수 있다. index.html, style.css, logic.js, app.js의 상대 경로를 유지한다. 배포 대상·접근 범위는 사용자가 지정한 설정을 따른다. 이 소스 묶음에는 기존 배포 사이트의 자격증명·Git 내부정보·호스팅 식별자를 포함하지 않는다.
